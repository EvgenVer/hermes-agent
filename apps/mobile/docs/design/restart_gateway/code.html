Service recovery

Restart gateway

A controlled restart can briefly interrupt messaging.

Restart Hermes gateway?

The messaging gateway and serving/control process are different. A fully stopped Hermes process cannot restart itself, and the app socket may remain connected during recovery.

What will happenRequest restart, check gateway state, reconnect if needed, then verify recovery from refreshed status.

Recovery sequence

1Requested · waiting for authoritative acknowledgement
2Checking gateway state
3Reconnecting if needed
4Confirmed recovery and refreshed status
Outcome unknown: an HTTP acknowledgement, helper exit, or public health response alone does not prove recovery.
Progress / timeoutKeep the current step visible without promising a fixed recovery duration.
ErrorShow the server error and leave status available for a fresh check.
Socket remains connectedDo not imply that every agent halted or that the app must disconnect.
